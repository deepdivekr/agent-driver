# Phase 106: 비코딩 Pack Work 등록용 예시

기본 Pack 9종 중 `coding.orchestrate`를 제외한 8종의 등록 문구다. 대상 사이트·기록·날짜·변경값을 정했으며, 개인 받은편지함이나 업무 시스템의 접근 권한을 가정하지 않는다. 공개 자료를 읽고 Office 안에 초안·파일을 만드는 범위다. 등록, 수동 출처 확인, 실제 Work 실행, 완료 검증은 각각 별도 상태로 남긴다.

2026-09-30 BrowserOS Neo에서 아래 공식 페이지의 공개 내용을 직접 확인했다. 이 확인은 설치된 Office Pack의 연결·실행 성공 증거가 아니다. 아래 문구로 Work를 등록할 때 실행·제출·예약·외부 메시지·주기 실행을 함께 시작하지 않는다.

## 1. research.search

> 기상청 https://www.weather.go.kr/w/weather/land/city-obs.do 의 서울 지점과 에어코리아 https://www.airkorea.or.kr/web/realSearch?pMENU_NO=97 의 서울 중구 도시대기 측정소를 각각 읽어 최신 기온(℃)·습도(%)·일강수(mm)와 PM-2.5(㎍/㎥)를 비교해줘. 출처별 관측 시각, 조회 시각, 지점 이름과 URL을 표에 넣어줘. 서울 기상관측소와 중구 대기측정소를 같은 지점으로 합치지 말고, 시점 차이·잠정자료·빈 값은 그대로 표시해줘. 결과는 Office 안의 보고서로만 남겨줘.

완료 기준: 두 공식 출처의 값과 단위·지점·시각을 각각 재대조한다. 빈 강수량을 `0`으로 바꾸지 않는다. 사이트 오류와 미관측을 분리하며, 한 출처를 못 읽으면 비교 완료로 표시하지 않는다. 에어코리아 직접 URL이 오류면 같은 공식 홈페이지의 실시간 자료조회 메뉴에서 현재 경로를 확인한다.

## 2. portal.collect

> 세계은행 https://data.worldbank.org/indicator/SP.POP.TOTL?locations=KR 에서 대한민국(KOR)의 총인구 지표 SP.POP.TOTL, 2015년부터 2024년까지를 수집해줘. 공식 CSV 내려받기 링크의 원본 파일을 Office 산출물로 보존하고, 국가 코드 KOR·지표 코드 SP.POP.TOTL과 정확히 일치하는 행에서 해당 10개 연도를 추출해 wb-kor-population-2015-2024.csv를 별도로 만들어줘. 열은 country_code,indicator_code,year,population,unit,source_url로 하고 단위는 명으로 적어줘. 결측은 빈 값으로 보존해줘. 출처의 갱신일이 있으면 기록하고, 원본·출력의 바이트 수와 SHA-256, 연도별 값과 총 10행을 다시 읽어 확인해줘. 다른 국가나 총인구 이외 지표를 섞지 마.

완료 기준: 공식 내려받기 결과의 실제 파일 형식·압축 여부·CSV 헤더와 메타데이터 행부터 확인한다. 제목이나 고정 행 번호로 자료를 선택하지 않는다. `KOR + SP.POP.TOTL + year`가 유일한 10행이어야 한다. 결측이 있으면 행은 남기고 결측 수를 보고한다. 2025년 자료가 있어도 지정 범위에 추가하지 않는다. 이 Work의 검증된 CSV가 7번 Work의 입력이다.

## 3. form.draft-submit

> 서울도서관 공개 행사 https://lib.seoul.go.kr/lecture/applyDetail/7422 의 '10월 작가힙톡(Hip-Talk) - (지웅배) 화성에 도시를 세운다면'을 읽고 신청 검토 초안을 Office에 작성해줘. 검토 대상은 2026-10-16 19:30–21:00 행사, 성인 1명이고 관심 사유는 '화성 이주에서 과학기술과 사회적 조건이 어떻게 연결되는지 알아보고 싶다'야. 공개 안내와 대조한 행사명·일시·장소·비용·신청 대상·접수 마감·조회 시각, 그리고 이 관심 사유를 담아줘. 모집 마감이나 조건 변경이 보이면 그대로 표시해줘. 이름·전화번호·주소·회원 여부·촬영 동의를 만들거나 대신 입력하지 말고 로그인, 신청 버튼, 동의 체크, 자리 확보는 하지 마. 완료 범위는 공개 정보로 작성한 로컬 검토 초안이야.

완료 기준: 행사 ID `7422`와 공개 상세 내용을 대조한다. 참가 인원·관심 사유는 이번 요청의 입력이며 사이트에 관측된 신청 내역으로 쓰지 않는다. 신청 페이지에 입력한 초안, `pre-submit capture`, 신청 완료 또는 좌석 보장을 주장하지 않는다. 공개 안내는 신청에 회원 로그인과 개인 정보 확인이 필요하다고 명시한다. 이는 향후 실제 신청의 조건이며 현재 로컬 초안 완성을 막는 입력 요청은 아니다.

## 4. record.update

> 서울도서관 공개 문의 https://lib.seoul.go.kr/bbs/content/1_68205 '위치기반 전자책 이용안내를 읽고'를 읽고 Office 검토용 사본을 만들어줘. source_id=1_68205, source_url, 공개 제목·작성일, 목록에서 확인한 처리상태만 원문 근거로 저장하고, 새 Office 메타데이터 review_label은 '미분류'로 초기화해줘. 사본을 다시 읽은 다음 review_label만 '전자책 이용 안내'로 바꾸는 수정 제안 JSON과 변경 전후 표를 별도로 작성해줘. 초기 '미분류'는 Office가 만든 값임을 명시하고 도서관 원본 필드로 표현하지 마. 사본의 원래 파일과 원문 필드는 보존하고, 비공개 답변은 읽거나 추정하지 마. 도서관 게시글·처리상태·답글은 변경하지 마.

완료 기준: 공개 기록 ID와 로컬 사본 해시를 고정한다. 제안에는 `review_label: 미분류 → 전자책 이용 안내` 한 필드만 포함한다. 사이트의 처리상태와 Office의 검토 분류를 구분하고, 비공개 답글 내용은 `unobserved`로 남긴다. 결과는 별도 수정안 파일이며 외부 티켓 수정이나 기존 개인 업무기록 접근 성공이 아니다. 실제 외부 `record.update` 타깃은 이 예시에 연결하지 않는다.

## 5. inbox.triage

> 서울도서관의 공개 문의함 https://lib.seoul.go.kr/bbs/list/1 에서 작성일이 2026-09-01부터 2026-09-30인 공개 글만 최근순으로 최대 10건 읽고 '전자책·온라인 서비스 / 도서·자료 신청 / 시설·이용 환경 / 프로그램 / 기타·판단 보류'로 분류해줘. 출처 URL·게시글 ID·작성일·제목·공개 처리상태·분류 근거를 남기고, 각 글에 내부 검토용 응답 제안을 최대 두 문장으로 써줘. 공식 답변을 읽지 못하면 읽지 못했다고 표시하고, 도서관 직원의 확정 답변처럼 쓰지 마. 상시 안내·기간 밖 글·비공개 글은 제외 사유와 개수만 남겨줘. 작성자 아이디와 개인 연락처는 수집하지 말고 답변 게시·메일 전송·읽음 처리·보관·라벨 변경은 하지 마.

완료 기준: 게시글 ID로 중복을 제거하고 포함·제외 수를 확인한다. 공개 글이 10건 미만이어도 다른 기간이나 비공개 글로 채우지 않는다. 공개 글의 답글이 비공개일 수 있다. 목록의 '답변완료'와 답변 본문 관측 여부를 별도로 기록한다. 이는 실제 공개 문의 큐의 분석이며 사용자의 개인 받은편지함 연결을 가정하지 않는다.

## 6. monitor.watch

> 기상청 https://www.weather.go.kr/w/special-report/overall.do 를 한 번 읽어 서울에 해당하는 호우 특보와 호우 예비특보의 현재 기준선을 Office에 남겨줘. 특보 종류·수준·대상 구역·발표 시각·발효 시각·해제 상태·조회 시각·출처 URL을 구분해줘. '없음'은 공식 본문을 확인했을 때만 적고 페이지 실패나 빈 표만으로 없다고 판단하지 마. 이후 30분 간격으로 같은 필드를 비교해 새 발표·주의보와 경보 간 변경·해제 때만 알리는 규칙을 초안으로 적어줘. 이번에는 조회 1회만 수행하고 감시 일정, watch tick, 자동 재조회, 외부 알림은 등록하지 마.

완료 기준: 현재 기준선과 향후 규칙을 다른 산출물/필드로 남긴다. 제안 간격은 `1800`초, 비교 대상은 종류·수준·구역·발표·발효·해제다. 요청한 조회 자체의 성공을 독립 확인하며, 기준선 생성으로 지속 감시가 활성화됐다고 표시하지 않는다. 현재 날짜와 발표 날짜가 다르다는 이유만으로 특보를 최신으로 다시 작성하지 않는다.

## 7. file.pipeline

> '세계은행 한국 인구 2015–2024 수집' Work에서 완료 검증된 wb-kor-population-2015-2024.csv를 입력으로 받아 원본을 보존하고 wb-kor-population-change-2015-2024.csv를 새로 만들어줘. 입력의 Work·run·artifact 식별자와 SHA-256을 확인한 뒤 country_code=KOR, indicator_code=SP.POP.TOTL, 2015–2024 각 1행과 인구 단위 명을 검증하고 연도 오름차순으로 정렬해줘. 기존 열에 population_change와 population_change_pct를 추가하되 2015년은 비교할 2014년 입력이 없으므로 두 값을 비워둬. 나머지는 당해 인구-전년 인구와 그 차이/전년 인구×100으로 계산하고 비율은 소수 넷째 자리까지 반올림해줘. 전년 누락·0·결측은 계산하지 말고 사유를 남겨줘. 출력 10행과 전년 연결, 정상 값이면 증감 합계=2024 인구-2015 인구를 다시 확인하고 원본 해시가 같은지 대조해줘. 파일이 아직 없으면 수집 Work 결과 대기로 남기고 임의 샘플을 만들지 마. 외부로 업로드하지 마.

완료 기준: 2번의 검증된 실제 Office 산출물이 선행 조건이다. 등록 시 새 두 Work의 식별자를 서로 연결하고 실행 시 검증된 run/artifact로 입력을 고정한다. 제목만 느슨하게 매칭하거나 파일 시스템에서 비슷한 이름을 검색하지 않는다. 수집 Work 등록은 입력 파일 생성이 아니다. 선행 Work가 재실행돼도 입력을 조용히 바꾸지 않는다. 공개 문서에는 개인 절대경로나 실제 Work ID를 넣지 않는다.

## 8. choose.stage

> 코레일 https://www.korail.com/ticket/main 에서 2026-10-07 서울역→부산역 편도, 성인 1명, 일반실, 직통, 출발 09:00 이상 12:00 미만인 열차를 조회해 출발시각 순으로 최대 5개 비교해줘. 열차번호·종별·출발·도착·소요시간·1인 편도 요금·표시된 좌석 상태·조회 시각·URL을 남겨줘. 우선순위는 12:00 이전 부산 도착, 그중 저렴한 요금, 동률이면 빠른 출발이야. 조건을 모두 만족하는 후보가 없으면 없다고 밝히고 조회 범위 안에서 가장 가까운 후보를 별도 표시해줘. 추천 후보 1개를 Office 안의 선택 초안으로만 남겨줘. 로그인·장바구니·예약·결제·회원가입·알림 신청은 하지 마. 날짜가 지났거나 해당 날짜 조회가 아직 열리지 않았으면 다른 날짜로 바꾸지 말고 그대로 보고해줘.

완료 기준: 조회 조건과 실제 결과를 대조한다. 가격·좌석 상태를 읽지 못한 후보는 미확인으로 표시하고 최저가·예약 가능을 확정하지 않는다. 실제 예약 번호나 장바구니 readback을 만들지 않는다. 공개 조회까지 로그인/제한이 나타나면 그 경계에서 멈춘다. 등록 시점의 페이지 열림은 이 조건의 실제 조회 성공과 다르다.

등록 준비에는 저장소의 `src/taskpacks/base-pack-catalog.ts`에 있는 위 8개 family를 사용한다. 등록 영수증에는 family·제목·요청 본문·새 Work ID·현재 정의 revision·연결된 선행 Work를 다시 읽어 대조한다. 실제 Work ID와 로컬 파일 binding은 비공개 영수증에만 남긴다. 결과 생성은 아직 수행하지 않았으므로 `prepared`와 `executed/verified`를 섞지 않는다.

실행에는 Office에 등록된 읽기 가능한 브라우저/공개 HTTP source와 Office 소유 산출물 쓰기 경로가 필요하다. 이 문서의 Neo 출처 확인은 Office에 브라우저나 source를 등록하지 않는다. 쓰기 family 3종은 외부 target을 임의로 추가하지 않고 로컬 초안까지만 수행한다. `runtime_pack_run`용 recipe와 실제 source/target 계약을 아직 구성하지 않았다면 family 이름만으로 Pack 실행 준비가 끝났다고 표시하지 않는다. 7번은 2번의 결과 생성·검증 전까지 결과 대기다. 실제 로그인·신청·외부 기록 수정·예약으로 범위를 넓힐 때에는 대상별 연결과 별도 승인이 필요하다.

원래 조사 후보였던 서울도서관의 `/rwww/html/ko/service/hopeBook.jsp`는 페이지 없음으로 확인돼 사용하지 않았다. 공식 홈페이지의 희망도서 안내 경로는 `/rwww/html/ko/hopeBook.jsp`지만, 회원·도서 입력을 가정하지 않도록 이번 등록 대상은 공개 정보가 확정된 행사 검토 초안으로 정했다. 조사 중 브라우저 일괄 호출 1회가 30초 제한에 걸렸고 이후 기존 탭의 도착 페이지를 다시 읽었다. 이 실패와 단순 페이지 확인을 Work 성공 기록으로 바꾸지 않는다.
