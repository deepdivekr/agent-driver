# 업무 인계와 실행 주체

Office는 업무의 목적·기록·승인·재개 지점을 관리한다. 모든 연결 에이전트에게
같은 도구 순서를 강제하지 않는다. Agent Driver 자체는 Node.js 런타임이고,
Hermes는 별도로 연결할 수 있는 실행 에이전트다.

| 실행 경로 | 실행 순서·도구·스킬을 고르는 쪽 | Driver가 담당하는 범위 |
|---|---|---|
| 가져온 Hermes 업무 | Hermes의 모델과 활성화된 스킬/도구 | ACP 세션, 지시 큐, 일회 승인 응답, 진행·답변 기록, 중단·재개 |
| 원격 OpenClaw 업무 | 원격 OpenClaw | 원격 세션 연결, 승인한 지시 전달, 관측·중단·불확실한 전송의 재전송 방지 |
| Driver 관리 Pack/고정 코딩 단계 | 상위 계획 모델 + Driver의 검증된 단계 계약 | 단계·실행기·허용 작업·인계·완료 근거 검사 |
| 대화형 코딩 | 사용자/상위 에이전트가 한 턴을 지시하고 Codex가 실제 작업 | 정확한 CLI 세션 재개, 답변·조언 분리, 사용자 다음 지시 대기 |

## Hermes의 스킬

TypeSafe의 182개 Hermes Skill 선택 사례는 해당 평가의 카탈로그다. 현재 설치의
스킬 개수나 모든 스킬의 실행 가능 여부를 뜻하지 않는다. 설치 버전, 프로필,
활성화 상태, 필요한 도구·인증에 따라 사용할 수 있는 스킬이 달라진다.

Hermes가 ACP 세션에 노출하는 도구와 스킬은 해당 설치 버전과 프로필에 따른다.
Driver는 Hermes의 스킬을 복사하거나 전부 실행 가능하다고 가정하지 않는다.
연결된 Hermes가 사용할 수 있는 스킬을 선택하며, 연결 성공만으로 특정 스킬의
실제 실행까지 검증된 것은 아니다.

Driver의 Hermes 프롬프트는 Family/추천 단계를 분류·참고로 취급하고 Hermes가
자체 스킬과 도구를 선택하도록 명시한다. 별도 Jev 스킬 선택기를 중복 호출하지
않는다. 스킬이 권한을 추가하지 않으며, 모델·인증·예약 소유권은 Hermes에 남는다.
Hermes 내부 도구의 모든 동작이 Driver의 MCP를 경유하는 것은 아니다. Driver의
기록이나 프롬프트를 Hermes 전체에 대한 OS 샌드박스·강제 보안 경계로 설명하지 않는다.

## 필수 인계 맥락

`src/work/continuity-context.ts`는 추가 모델 호출 없이 다음을 구성한다.

- 프로젝트·Work·실행 ID와 revision, 실행 주체.
- 목표와 완료조건, 시간순 사용자 지침 또는 현재 코딩 단계 지침 전문.
- 허용 범위와 재실행 제약, 실행 상태·불확실한 효과·근거 참조.
- 다음 행동과 별도의 참고 답변 발췌. 참고자료는 새로운 지시가 아니다.
- 전달 문서의 해시. 해시는 동일성과 결속만 검증하며 내용의 진실성은 보증하지 않는다.

Hermes는 각 지시 전 Office에 저장된 이전 지시와 상태를 직접 전달받는다. 이전
답변·가져온 이력은 보조 자료이고, 사용자 검토나 `end_turn`은 독립적인 업무 완료
검증으로 승격하지 않는다. 전달한 문서는 같은 SQLite의 `hermes_turn_context`에
턴과 결속해 저장한다. 기존 원본 기록은 삭제하거나 요약으로 덮어쓰지 않는다.

고정 코딩 단계는 `.git/agent-driver/handoffs/` 문서에 같은 계약을 포함한다.
350자 이후에 있던 단계 지침도 유지한다. 모델의 검토 답변과 코드가 실행한 검사
영수증을 구별한다. 기존 Git 상태 대조, 모델 고정, 구독→유료 API 자동 전환 금지는
변경하지 않는다. 최신 단계 수정은 SQLite에서 다시 구성된 계획을 따른다.

필수 정보는 96,000 UTF-8 bytes 이내이며 초과 시 `CONTINUITY_CORE_TOO_LARGE`로
호출 전에 멈춘다. Hermes의 이전 턴은 128개까지 보존하며 이를 넘으면
`CONTINUITY_HISTORY_REVIEW_REQUIRED`로 명시적인 기록 정리를 요구한다. 몰래 과거
지침을 버리는 자동 압축은 없다. 보조 기록만 총 8,000 bytes/개별 2,000 code points
이내로 발췌하며 제외 참조를 기록한다. 알려진 비밀 패턴은 발췌 전에 마스킹한다.
비밀 패턴 검사는 완전한 민감정보 탐지기가 아니다.

## 적용 범위

이번 연결은 **Hermes 관리 업무와 고정 코딩 인계**다. 대화형 Codex, 원격 OpenClaw,
일반 Pack/Swarm의 모든 내부 메시지를 이 형식으로 교체한 것은 아니다. 기존 구조화
모델 실패 시 인계는 같은 입력을 다음 허용 클라이언트에 전달하는 경로를 유지한다.
유료 호출·기존 업무 실행·원격 서버 변경·운영 서비스 재시작은 이번 검증에 포함하지 않는다.
