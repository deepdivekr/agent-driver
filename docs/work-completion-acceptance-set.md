# Work 완료 공개 수용 세트 (A7)

Authority: [Work 완료 경로 복구 및 자율 운영 계획](work-completion-and-autonomy-plan.md) A7.

이 세트는 실제 구독 모델로 Part A의 완료 경로를 확인하기 위한 공개 업무 7건이다.
누구나 같은 입력으로 다시 돌릴 수 있도록 공개 출처와 저장소 안의 예시 파일만 쓴다.
비공개 원본 24건(Phase112 matrix)은 사용자 환경에서만 돌리고, 공개 기록에는 수치만 남긴다.

fixture 테스트 결과는 이 세트의 결과가 아니다. 이 세트는 실제 모델 호출이 있어야 하며,
이 저장소의 CI·개발 컨테이너에서는 실행하지 않았다(개발 컨테이너 기록은 `NOT_RUN`).

## 실행 방법

1. Control Center에서 Work 모델과 검증 모델을 실제 구독 모델로 설정한다.
2. 각 업무를 아래 문장 그대로 새 Work로 등록하고, 사람 개입 없이 끝날 때까지 둔다.
   승인이 필요한 단계가 나오면 그 사실을 기록한다(이 세트는 승인이 필요 없어야 한다).
3. Work 상세의 활동 기록에서 다음을 옮겨 적는다.
   - 최종 상태(`succeeded` / `awaiting_review` / `failed` / 대기 상태)와 이유 코드
   - `supervisor.verification.calls` 활동의 검증 모델 호출 수
   - 검증 방식(`WORK_COMPLETION_LIGHT_VERIFIED`이면 가벼움, 아니면 엄격)
   - 등록부터 완료까지 걸린 시간, 수정(`Correction n/3`) 횟수
4. 성공 건은 산출물을 열어 요청을 실제로 만족하는지 확인한다(거짓 성공 확인).
   거부·보류 건은 거부 이유가 맞는지 확인한다(거짓 거부 확인).
5. 실패 원인을 `업무 불가능 / 검증 오판 / 실행기 종료 / 환경` 중 하나로 분류한다.

### P3·P4 예시 파일

별도 폴더에 `sample.json`을 아래 내용으로 만들고 host 설정의 `packs.sources`에
`{"id":"records","kind":"file","path":"sample.json","format":"json"}`로 등록한다.

```json
[{"id":"a1","name":"Alpha","status":"active","type":"report"},
 {"id":"a2","name":"Beta","status":"inactive","type":"memo"},
 {"id":"a3","name":"Gamma","status":"active","type":"memo"},
 {"id":"a4","name":"Delta","status":"active","type":"report"},
 {"id":"a5","name":"Epsilon","status":"inactive","type":"invoice"},
 {"id":"a6","name":"Zeta","status":"active","type":"invoice"}]
```

- P3 정답: a1, a3, a4, a6 네 행, 열은 id와 name만.
- P4 정답: report 2, memo 2, invoice 2 (합계 6).

## 지표

- 완료율: `succeeded` 건수 / 7. 목표 70% 이상(사용자 확인 필요).
- 거짓 거부율: 거부·보류 건 중 산출물이 실제로 요청을 만족한 비율.
- 거짓 성공률: 성공 건 중 산출물이 요청을 만족하지 않은 비율. 0이어야 한다.
- Work당 검증 호출 수와 소요 시간.
