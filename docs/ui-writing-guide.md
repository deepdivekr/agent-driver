# 관제센터 문구 기준

기준: [토스 UX Writing의 8가지 원칙](https://toss.tech/article/21022).
2026-10-02 관제센터의 한·영 안내, 버튼, 상태, 입력 도움말에 적용했다.

- 사용자가 할 일과 그 결과를 먼저 쓴다. 버튼은 다음 행동을 짧게 말한다.
- 한 문장에는 핵심 내용 하나만 넣는다. 중복 설명과 내부 구현 용어를 줄인다.
- 한국어 설명은 자연스러운 해요체를 쓴다. 영어는 같은 의미의 간결한 표현을 쓴다.
- 용어를 통일한다: 업무, 완료 기준, 결과 받을 곳, 실행 도구, AI 앱, 사용자 확인.
- 저장, 실행, 확인된 완료, 전달을 구분한다. 연결 설정 저장을 연결 성공으로 표현하지 않는다.
- 요금, 권한, 미확인 상태와 지원하지 않는 기능은 짧게 쓰되 숨기지 않는다.
- 제품 문구만 바꾼다. 업무 제목·사용자 지침·AI 답변·산출물·기술 로그·명령·인증정보는 원문을 유지한다.

구현은 `src/observability/ui-copy.ts`의 검토 문구와 등록된 제품 문구만 대상으로
하는 표기 규칙, `ui-copy-extra.ts`의 추가 번역에 모았다. 동적 화면은
`officeCopy`를 통해 같은 문구를 사용한다. 원문 영역은 `data-i18n-skip`으로 보호한다.
새 문구는 한·영을 함께 추가하고 `runtime-ui-copy`와 해당 화면 테스트로 확인한다.
기존 저장 기록의 제품 안내는 표시할 때만 번역하며 저장된 내용은 수정하지 않는다.
