# alpha.18 Swarm: 실제 6개 사이트 조사와 제한된 복구

2026-09-23 Ubuntu/WSL에서 공개 사이트 6곳을 병렬로 관측하고 한국어 조사 메모로 종합했습니다. 마지막 수정 검증 `run-08`은 **223,780ms(3분 43.8초), `completed`, 종료 코드 0**으로 끝났습니다. 취합 단계에 넣은 timeout 1회는 같은 실행 안에서 자동 복구됐고, 최종 품질 점수는 **0.85**였습니다. 실행기는 실제 브라우저 화면, 공식 구독 CLI의 LLM, Jev API를 사용했습니다.

호출 경로는 `scripts/live-visual-research.mjs`의 **프로세스 내부 `RuntimeApi.call`**입니다. MCP 도구와 같은 런타임 구현을 실행했지만, 이 기록 자체가 stdio MCP 왕복이나 상위 Hermes의 sub-agent 소환을 검증한 것은 아닙니다. 별도의 [6종 Pack 실사례](evaluation-live-alpha-18.md)가 실제 stdio MCP를 검증합니다.

## 범위

Karpathy, Amodei, Shumer, Garry Tan, Anthropic News, Simon Willison의 공개 사이트를 각각 독립 source worker로 관측했습니다. 뒤이어 reducer 1개와 synthesizer 1개가 근거를 선택·종합합니다. 목표는 근거가 있는 사실 3개 이상, 해석으로 표시한 적용점, 출처와 한계를 포함한 메모입니다.

이는 **6개 사이트의 제한된 조사 메모**입니다. 기존 23인·영상 조사 전체, 모든 최신 글의 탐색, 로그인된 SNS 조사, 카드 PNG 제작 완료를 뜻하지 않습니다.

## 마지막 실행의 실제 결과

새 코드의 회귀 검사를 마친 뒤 수정 검증은 한 번만 실행했습니다. 이전 LLM 계획과 source 자료를 재사용하되, 목표·URL 범위·1시간 이내 기록·receipt hash를 확인하고 실제 사이트의 랜딩 페이지를 두 번씩 열어 원문 문구를 대조했습니다. 이전 30개 카드 중 현재 화면에서 다시 확인된 **12개만** 유지했습니다. 따라서 이 시간은 **warm-cache 재검증**의 기록이며, 계획 생성이나 완전한 신규 조사 시간과 비교하면 안 됩니다.

source 6개는 병렬로 시작했으며 표의 시간에는 순차 처리된 품질 평가 대기도 포함됩니다. 합산하면 전체 경과 시간이 되지 않습니다. 최종 문서에는 6개 사이트 각각의 범위·선별 이유와 한계를 명시했습니다. 최종 gate는 score 0.75 및 evidence 0.75 그대로였고, 결과는 relevance 1 / evidence 0.75 / usability 0.75였습니다.

`standard` 모드이지만 **호스트에서 조정한 실행 profile**입니다. 목표 600초, 전체 마감 900초, profile worker 상한 180초, 실제 계획의 worker timeout 120초, 종합 예비 시간 120초입니다. 기본 Standard의 목표 180초·마감 240초·worker 75초 조건을 검증한 기록은 아닙니다.

런타임의 `close`/`drain` 반환과 프로세스 정상 종료를 확인했습니다. 해당 run의 남은 lease는 0, DB의 브라우저 화면 6개는 모두 `closed`, active는 0이었습니다. 기존 관제센터 프로세스는 보존했습니다. 별도 OS 수준에서 모든 브라우저 자손 프로세스를 전수 대조한 것은 아닙니다.

## 실패를 남기고 고친 내용

| 실행 | 경과 시간 | 결과 | 확인한 문제 |
|---|---:|---|---|
| run-05 | 211,962ms | FAIL | 6개 source는 완료했지만 최종 품질 0.70으로 0.75 기준 미달 |
| run-06 | 137,953ms | FAIL | 관측 링크의 fragment 차이를 다른 URL로 판단했고, 한 source의 검토 상태가 독립 실행 중인 다른 source까지 중단 |
| run-07 | 350,027ms | FAIL | 6개 source 완료, reducer timeout 자동 복구 성공. 최종 문서는 1회 보정 뒤에도 0.70으로 미달 |
| run-08 | 223,780ms | PASS, 제한된 메모 범위 | source 6개 warm-cache 재검증, reducer timeout 1회 자동 복구, 최종 문서 첫 시도 품질 0.85 |

run-06의 예정된 timeout 주입은 reducer에 도달하지 못해 실행되지 않았습니다. run-07에서는 reducer 첫 시도에 `CLIENT_TIMEOUT`을 **정확히 1회 주입**했습니다. 같은 실행 안에서 reducer만 다시 배정되어 성공했고, 앞선 source 작업을 다시 실행하지 않았습니다. 다만 최종 품질 검증에 실패했으므로 전체 성공으로 계산하지 않습니다.

복구는 읽기 전용의 명시된 기술 오류에 한정하고 시도 수·lease·전체 마감 시간을 유지합니다. 인증, 사용자 승인, 효과가 불확실한 외부 쓰기를 기술 오류처럼 자동 재시도하지 않습니다. 이미 실행 중인 독립 reader는 다른 worker의 검토 상태에도 관측을 마칠 수 있지만, 새 lease는 배정하지 않으며 사용자 로그인 handoff와 동시에 화면을 조작하지 않습니다.

## 최종 품질 입력을 좁혀 재검사

run-07의 최종 평가에는 6개 사이트 조사라는 요청과 선택된 최종 사실만 전달되고, 나머지 사이트의 실제 관측 근거가 빠져 있었습니다. 따라서 최종 문서와 인용을 바꾸지 않고, 코드가 기록한 선행 worker의 관측 URL·readback·사실 수를 평가 입력에 추가한 **1회 진단 재생**을 수행했습니다.

9,606ms 후 점수는 0.70에서 0.80으로 바뀌었습니다. 0.75 기준은 그대로입니다. 입력 누락이 영향을 주었다는 단일 관측이며, 통계적 보정 완료나 정답 판정의 증명은 아닙니다. run-07의 FAIL 기록을 PASS로 변경하지 않았습니다.

수정된 최종 출력 계약에는 6개 사이트 각각의 조사 범위와 직접 인용하거나 제외한 이유도 포함됩니다. 선행 worker가 성공했다는 사실만으로 최종 문서를 통과시키지 않으며, 근거 없는 claim과 낮은 품질은 계속 거부합니다.

## 비용과 해석의 한계

run-08에서는 Codex 구독 LLM **18회**, 입력 **296,106토큰·출력 3,348토큰**이 기록됐습니다. 캐시 입력 150,400토큰은 입력 합계에 이미 포함됩니다. Jev는 **16회**, 입력 **38,171토큰·출력 987토큰**입니다. 사용량 누락 호출은 없었습니다. worker별 사용량은 공개 JSON에 있습니다.

Jev 왕복 시간은 최솟값 593ms·p50 667ms·최댓값 934ms였습니다. 32개 typed judgment 중 accepted 1개, review 30개, no-match 1개였고 confidence 범위는 0.12~0.81, 중앙값 0.53이었습니다. accepted 1개도 같은 평가 묶음의 다른 차원이 검토 대상이었으므로, **16개 판단 묶음 모두 LLM 보정으로 이어졌습니다. 이 실행의 Jev 단독 fast-path 완료는 0개입니다.**

비교용 실패 run-07은 LLM 27회, 입력 528,594·출력 13,931토큰, Jev 16회, 입력 51,472·출력 962토큰이었습니다. 실행 간 근거 수·캐시 범위·출력 계약이 달라 속도 개선 비율로 비교하지 않습니다. 반복 품질 평가와 LLM 보정 비용이 크므로 이 실행으로 속도·비용 우위를 주장하지 않습니다.

Jev의 `confidence`는 선택지 분포의 집중도이며 p-value나 정답일 확률이 아닙니다. 이번 `swarm.control.provisional`은 도메인 calibration이 완료된 profile이 아니므로 Jev fast-path 성능이나 전체 정확도를 입증한 것으로 해석하면 안 됩니다. 기존 ChatGPT Work 작업의 비교 가능한 기준 시간도 확보하지 않았습니다.

재사용한 LLM 계획에는 각 source에서 카드 3개 이상이라는 문구가 있지만, 현재 source 완료 계약의 강제 조건은 아닙니다. 이번에는 일부 source에서 1~2개만 확인했습니다. PASS는 최상위 요청의 제한된 메모 목표와 최종 품질 gate에 관한 것이며, 계획에 적힌 모든 세부 희망조건의 충족을 뜻하지 않습니다. 이를 구분하는 계획·검증 계약 보강은 남은 과제입니다.

[공개용 지표 JSON](evidence/swarm-recovery-alpha18.json)에 실패 기록, 진단 재생과 원시 파일 hash를 남겼습니다. 원시 모델 응답·웹 원문·개인 절대 경로·인증 정보는 공개 자료에 포함하지 않습니다.
