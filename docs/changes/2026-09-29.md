## 29일 밤부터 이어진 후속 변경 — 이번에 커밋

Phase 104~106은 29일 밤부터 30일로 이어졌다. 아래 전체가 29일 안에 끝났다는 의미는 아니다.

- **이슈 정리:** 중복 이슈 7개의 미완료 조건을 별도 이슈에 모았고, 원인 미확정 실패는 남겼다. 닫힌 중복 이슈를 기능 완료로 표시하지 않았다. 백업 스키마 설명도 실제 구현에 맞췄다.
- **접수 즉시 실행:** 신규 Work는 접수 후 상세 화면으로 이동해 분석과 현재 실행을 진행한다. 연결·필수 선택이 없으면 이유를 표시한다. 프로젝트 가져오기만으로 기존 봇을 중복 실행하지 않는다.
- **관제 화면:** 실제 Pack·출처·담당자·중단 이유를 읽기 쉬운 타임라인으로 표시하고, 단계 클릭 모달에서 일시정지·지침 변경·재개를 제공한다. 실행 근거 없는 “진행 중” 표시를 줄였다.
- **브라우저 복구:** 공개 읽기 작업의 기술적 실패는 연결된 환경으로 인계한다. Google 비정상 트래픽의 확인된 경우에는 같은 검색을 Aside로 넘기는 경로를 구현했다. 로그인·CAPTCHA·불확실한 쓰기 결과는 별도 확인 경계를 유지한다.
- **로그인 프로필:** 환경별 사전 로그인과 Office 전용 저장 프로필을 추가하고 Work·Swarm·Pack이 같은 지정 프로필을 재사용하도록 했다. 유휴 브라우저는 닫는다. 기존 Windows 인증정보 복사나 영구 로그인 보장은 아니다.
- **업무 연결 해제:** Office에서 연결을 끊어 향후 실행·예약·원래 런타임 제어를 막고 기록은 보존하는 기능을 추가했다. 개인 설치 초기화 요청은 복구 가능한 별도 보관으로 처리했으며, 이번 커밋 과정에서 복원하지 않았다.

## 9월 30일 오전 변경 — Phase 107~108

- **작업 규모에 맞는 Swarm:** 작은 조사까지 여러 명으로 강제 분해하던 조건을 완화했다. 필요한 최소 그래프로 계획하고 완료된 작업을 재실행하지 않는다.
- **기존 담당자 문맥 재사용:** 지원되는 Codex·Claude 판단 세션을 같은 Work·실행·역할·모델·지침에 묶어 재개한다. 유효하지 않은 세션은 체크포인트 경로로 돌아간다. 모든 외부 런타임의 대화를 동일하게 재개한다는 의미는 아니다.
- **구독 전용 역할 모델:** 기본 클라이언트, 앱별 기본 모델, 역할별 정책을 구분했다. 코딩 전용 설정은 우선하며 API 모드의 기존 선택은 바꾸지 않는다.
- **태스크 Auto 모델 배분:** LLM이 연결·확인된 구독 후보 안에서 계획·실행·검증·종합 역할을 한 번 배분하고 같은 태스크·설정에서는 저장된 배분을 재사용한다. 후보나 유효한 응답이 없으면 기본값을 사용하고 이유를 표시한다. 새 Jev 정책을 중복 삽입하지 않는다.
