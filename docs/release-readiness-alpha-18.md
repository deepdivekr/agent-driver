# Agent Driver alpha.18 검증 기록

## 범위

`0.1.0-alpha.18`은 Apache-2.0으로 공개하는 개발 alpha입니다. 이 문서는 테스트 환경, 실제 실행과 아직 검증하지 못한 범위를 구분합니다. 8종 전수검사는 모든 외부 서비스의 인증·쓰기까지 검증했다는 뜻이 아닙니다.

## 이번에 발견한 문제

2026-09-23 감사에서 실패 기록의 중복 방지는 동작했지만, 기록이 남은 작업을 이어가는 경로가 부족했습니다.

- 8종 공통 Family 경로에서 중단된 실행의 자동 재개가 부족했습니다.
- 수집 계열 5종은 원인을 복구한 뒤에도 같은 요청에 이전 실패만 반환했습니다.
- 병렬 조사에서는 기한 안에 도착한 결과가 내부 품질 검사 대기 중 만료되거나, 모델 시간 초과가 사용자 검토로 넘어갔습니다.

실패 기록은 보존하며, 수정 뒤의 회귀 검사와 실제 재실행을 별도로 기록합니다. 테스트 통과만으로 실사용 성공을 주장하지 않습니다.

## 검증 상태

2026-09-23 실제 공개 웹·로컬 자료를 사용한 **6종 경로**가 stdio MCP를 통해 6,743ms에 완료됐습니다. 공개 뉴스 30행 수집, 로컬 검색·CSV, 감시 상태의 MCP 재시작 지속성, Jev 1건 분류, 실제 연락 양식 7개 필드 미제출 초안을 확인했습니다. [단계별 결과·증거·재실행](evaluation-live-alpha-18.md)

`record.update`와 `choose.stage`의 실서비스 변경은 실행하지 않았습니다. 따라서 모든 8종의 실계정 검증 완료나 무감독 운영 완료를 선언하지 않습니다. 정상 실사례와 장애 복구 회귀는 별도 증거입니다.

고정된 원본의 기본 회귀는 **438/438 PASS**입니다. 분류는 unit 135, contract_fake 96, fixture_integration 76, native_integration 131이며 마지막 항목에는 검사 중 입력 해시가 바뀌지 않았다는 확인이 포함됩니다. 장시간 soak는 기본 회귀에서 제외했습니다.

개인 workflow를 제외한 clean 공개 사본은 **415/415 PASS**입니다(unit 122, contract_fake 94, fixture_integration 76, native_integration 123). 별도 설치·빌드와 의존성 감사에서 취약점 0건을 확인했습니다. 최초 공개 검사의 5건 실패는 테스트가 이전 MCP 버전 alpha.16을 기대한 문제였으며, alpha.18과 정확히 일치하게 수정 후 전체 재검사했습니다. 최초 실패 기록도 보존했습니다.

이 공개 사본에서 실제 6종 stdio MCP 작업을 다시 실행해 **10,959ms**에 완료했습니다. 실제 문의 폼은 7개 필드 입력과 읽기 재확인까지 수행하고, 제출 실행은 `PACK_DRAFT_ONLY`로 거부했습니다.

실제 프로세스 강제 종료 후 첫 소스 checkpoint를 유지해 두 번째 소스부터 재개하는 검사, 같은 요청의 중복 실행 방지, 정상 종료 중 접수 작업 완료, 설정 변경 작업이 복구 큐를 막지 않는 검사, 사용된 승인 재실행 거부가 포함됩니다. 병렬 조사에서는 기존 유효 worker의 화면·결과 접수를 유지하며 일부 worker의 검토 대기를 분리했습니다.

최종 Swarm 실사례는 **223,780ms에 completed**였습니다. 6개 공개 사이트에서 기존 근거 12개를 현재 페이지와 다시 대조했고, reducer에 시간 초과를 한 번 주입한 뒤 같은 run에서 해당 단계만 복구했습니다. source 재실행은 0회, 최종 품질은 0.85로 기존 0.75 기준을 통과했습니다. [worker별 시간·토큰·실패·복구 기록](evaluation-swarm-alpha-18.md)

이 Swarm은 프로세스 내부 RuntimeApi 호출, warm-cache 재검증, 조정된 600/900초 목표/마감 조건입니다. 기본 Standard 시간 조건의 성능 보장, MCP stdio 왕복이나 전체 카드뉴스 PNG 생성 검증은 아닙니다. Jev 16개 판단 묶음 모두 LLM 보정으로 이어져 Jev 단독 처리의 속도 우위도 입증하지 못했습니다.

GitHub 게시 후 자동 검사 결과는 저장소의 [Runtime checks](https://github.com/deepdivekr/agent-driver/actions/workflows/runtime.yml)에서 해당 commit과 대조할 수 있습니다. 위 수치는 게시 전 로컬에서 확인한 결과입니다.

## 유지하는 경계

- 로그인·CAPTCHA·사람의 승인은 우회하지 않습니다.
- 외부 변경의 결과가 불명확하면 확인 없이 같은 변경을 재전송하지 않습니다.
- 실패 기록과 중간 산출물을 지우고 성공으로 바꾸지 않습니다.
- 모델 확률, 정상 종료 코드, 테스트 개수만으로 업무 성공을 판정하지 않습니다.
- 실제 작업에 사용한 키·계정·개인 자료와 원시 로그는 공개하지 않습니다.

## 현재 제공하지 않는 보장

임의 사이트 자동 적응, 모든 실행기 사이의 자동 전환, 무제한 재시도, 꺼진 PC에서의 작업 지속, native Windows/macOS 전체 앱 제어를 보장하지 않습니다. 상주 감시에는 실행 중인 런타임이 필요합니다.
