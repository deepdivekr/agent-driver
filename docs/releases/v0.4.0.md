# Agent Office v0.4.0

## Work execution and visibility

- Submit a Work and follow its execution from the detail page.
- New AI plans describe outcome-based stages. Browser visits, tool calls and worker activity belong to those stages rather than becoming separate progress steps.
- Source attempts and actual observations are distinguished. Execution receipts do not by themselves prove that the requested result is correct.
- Pause, change direction and resume through the stage controls. Saved evidence is reusable only while the stage contract and its dependencies remain valid.
- An approved submission continues into execution after a successful definition retry. Definition-only requests and paused or disconnected Works remain inactive.
- Large completion-evidence sets use bounded inspection batches and a separate final judgment. Missing or contradictory evidence is not marked complete; completed actions are not repeated to repair verification.

## Connections and continuity

- Initial subscription model choices follow the connected CLI's current model list. Saved choices are retained, with a warning when a refreshed list no longer includes them; unsupported-model errors show a specific recovery instruction.
- Subscription-only automatic role selection, reusable responsible-agent sessions and optional Swarm decomposition.
- Persistent browser profiles with environment-specific login setup; account expiry or verification can still require the user.
- Read-only HTTP/2 navigation failures can hand off to an already registered, permitted browser. Login and access refusals do not trigger this transport recovery.
- Existing bots keep their original runtime. Imported configuration is separate from verified live control.
- No automatic subscription-to-paid-API fallback. Jev remains optional and follows the selected Pack's decision points.
- Completion verification has a separate model-response budget. A verification timeout preserves results and reports the cause; it does not silently lower the selected model or reasoning effort.

## Result delivery

- Optional private Telegram, Slack and Discord settings; app results remain available without a messenger.
- Instructions, explicit completion conditions and multiple destinations persist separately from AI plans.
- Independently verified output is dispatched automatically. The final stage shows destination receipts and supports changing unsent output and future destinations.
- Stored credentials are not presented as a tested connection. Ambiguous sends require reconciliation; changing a destination never replays an already delivered result.
- Imported bots retain their original runtime and sender. Messenger delivery sends result text, not every generated original file; those files remain downloadable in Work details. [Details](../work-delivery.md)

## Updating

Finish or pause active work and stop connected MCP clients and the Control Center before updating. Run the versioned installer, then reconnect clients. Existing data is preserved; personal credentials and workflows are not bundled.

Ubuntu 24.04 x86_64 and Windows 11 with WSL2 are the supported runtime environments. Native Windows desktop control remains experimental; macOS and additional guest transports are not certified by this release.

Publication requires the full quick regression suite, disposable fresh/upgrade installation checks, public-boundary checks and a separate actual-runtime research completion. Fixture tests are not presented as proof of live website success.
