# Agent Office v0.2.0

Manage existing agent work from one local Control Center. Agent Driver remains an
Apache-2.0 local MCP server; Hermes and OpenClaw keep their own runtime, credentials
and model settings.

## What's included

- **Hermes work import:** inspect local conversations or schedules, review a draft,
  and register a Work without starting it. Duplicate detection, source-change checks,
  local backup and atomic acceptance protect repeated imports. New instructions run
  through Hermes ACP, with progress, permission requests, pause and replies in Office.
- **Remote OpenClaw:** link an existing conversation or schedule over a human-registered
  SSH connection. Execution stays on the server. Sending an instruction requires local
  human review. Uncertain sends are reconciled rather than automatically replayed.
  Existing schedules are view-only; Office does not take over their scheduler.
- **Coding model preferences:** choose coding-specific planning/advice and CLI models,
  or inherit global settings. Existing attached CLI sessions keep their bound model.
  Subscription failures still never automatically switch to a paid API.
- **Continuity:** Hermes turns and fixed coding handoffs carry bounded, versioned
  instructions and evidence. Agent claims remain distinct from verified completion.
- **Browser setup:** allow up to 60 seconds for Chromium to start on a busy PC.
  A timeout is distinguished from a startup failure; the installer still verifies
  a real page and never installs system packages without the user.
- **One optional Jev recommendation for project imports:** inspect bounded, redacted
  code context and suggest at most one grounded opportunity, or none. Explain the
  baseline, expected benefit, required state and fallback. Users may skip Jev and its
  costs. This is a recommendation, not automatic code insertion or a measured speedup.

New Works use the selected Task Pack's existing Jev judgment points, subject to global
connection settings. Work definition does not create a second Jev policy. Explicit
per-Work OFF settings and imports accepted without cost consent remain OFF on upgrade.
The proposed separate Jev call/skip planning feature for newly prompted Works is not included.
No personal business adapters, server addresses, account records or credentials are bundled.

## Install or update

On Ubuntu 24.04 x86_64, or Ubuntu 24.04 inside Windows 11 WSL2:

```bash
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/deepdivekr/agent-driver/v0.2.0/install.sh | bash'
```

Before updating, finish active work and stop your existing MCP and Control Center.
Reconnect them after installation. The installer preserves `~/.agent-driver` and refuses
to overwrite modified or unmanaged installations. It does not hot-swap a running task.
Private customized installations must be migrated separately, not overwritten.

## Verification and limits

Publication is gated on quick regression, production dependency audit and isolated
real fresh-install / v0.1.0 and v0.1.1 upgrade checks. The probes run npm, the build,
Chromium, MCP and persisted Work/settings; model responses and remote services in CI
are synthetic. Chromium cache reuse is recorded. CI artifacts preserve failures too.

Native Windows/macOS, every third-party version, NAS hardware, live account workflows,
paid-model efficiency and long soak are not certified by these checks. Detailed boundaries
and receipts are described in [release readiness](https://github.com/deepdivekr/agent-driver/blob/v0.2.0/docs/release-readiness-v0.2.0.md).
