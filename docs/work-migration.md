# 기존 업무 가져오기 — Hermes 실행 유지

v0.2.0부터 제공하는 선택적 연결 기능입니다. 호환 Hermes 설치와 해당 실행 환경의
프로필이 필요하며, Agent Driver 설치만으로 Hermes 업무가 자동 등록되지는 않습니다.

Hermes에 맡겼던 업무를 Agent Office의 업무 목록에서 관리할 수 있습니다.
실행은 같은 Hermes 프로필이 맡습니다. 기존 로그인·모델 설정을 복사하거나 바꾸지 않습니다.
Jev는 필요하지 않습니다.

## 이용 순서

1. 관제센터에서 **가져오기 → Hermes 업무 → 가져올 업무 찾기**를 누릅니다.
   기본 프로필을 찾지 못하면 Hermes 데이터 폴더를 지정합니다. WSL에서 실행하는
   Driver에는 그 환경에서 접근할 수 있는 경로가 필요합니다.
2. 대화 또는 예약을 하나 선택합니다. 원본 근거와 확인할 사항을 읽습니다.
3. 업무 이름·목표·완료 조건·실행 지침을 확인하고 필요하면 고칩니다.
   자동 초안은 원본 지침을 옮긴 것으로, 과거 업무가 성공했다는 증명은 아닙니다.
4. 확인 체크 후 **확인하고 가져오기**를 누릅니다. 업무는 실행 대기 상태로 등록됩니다.
5. 업무 상세에서 새 지시를 보내면 Hermes 실행이 시작됩니다. 등록만으로는
   모델 호출, 사이트 조작, Telegram 전송, 예약 실행이 발생하지 않습니다.

에이전트에 “Hermes에서 하던 업무를 가져와줘”라고 요청해도 됩니다. MCP 도구로
원본 목록과 초안을 준비할 수 있지만 최종 등록은 사용자가 관제센터에서 확인합니다.
에이전트가 초안을 해석하는 데 쓰는 모델 사용량과 가져오기 자체의 동작은 별개입니다.
가져오기 자체는 AI·Jev를 추가 호출하지 않습니다.

## 원본을 얼마나 읽나요?

- 목록: 대화 제목을 50개씩, 예약 정의를 최대 500개까지 표시합니다.
- 선택한 대화: 최근 사용자·답변 12개를 읽습니다. 도구 로그와 숨은 추론은 제외합니다.
- 선택한 예약: 허용된 업무 정의 필드만 읽습니다. 예약을 Driver에서 다시 켜지 않습니다.
- 인증 파일·환경 변수 파일·설정 파일은 스캔하지 않습니다. 표시할 본문에서 알려진
  비밀값 형식을 가리지만, 공유 전에는 사용자가 본문을 확인해야 합니다.
- 원본 스키마가 다르거나 자료가 너무 크면 제한을 안내하고 멈춥니다.

기존 대화가 여러 업무를 포함하면 이번에 관리할 업무를 하나로 좁혀 주세요.
별도 모델·스킬·작업 폴더·스크립트 실행을 지정한 예약은 그대로 재현할 수 없어
등록을 막고 확인할 설정을 표시합니다.

## 재시도와 복구

| 상황 | 처리 |
|---|---|
| 같은 원본·같은 승인 내용을 다시 요청 | 같은 업무와 등록 기록 반환 |
| 여러 창에서 동시에 등록 | 활성 연결은 하나만 생성 |
| 검토 중 원본 변경 | 다시 읽고 확인하도록 안내 |
| 등록 도중 실패 | 부분 업무·부분 기록을 함께 되돌리고 재시도 가능 |
| 백업 실패 | 등록하지 않음 |
| 이전 수동 등록의 동일 출처 발견 | 기존 업무 안내, 덮어쓰기·중복 생성 차단 |
| 첫 실행 전 취소 | 연결만 취소, 원본과 기록 보존 |
| 실행을 요청한 이후 | 이전 취소 대신 업무 일시정지 사용 |

등록 전 Driver 데이터베이스 사본을 로컬에 보관합니다. 백업에는 개인 업무 기록이
들어 있으므로 외부에 공유하지 마세요. 중복 판단은 동일한 로컬 프로필·원본 ID·
확인 내용 기준이며, 서로 다른 대화를 의미만으로 합치지는 않습니다.

## 무엇이 그대로 남나요?

기존 Telegram 대화나 실행 중인 세션을 통째로 옮기는 기능은 아닙니다.
새 업무의 첫 실행은 전용 Hermes 세션에서 시작하고 그 이후 같은 세션을 이어갑니다.
기존 Telegram 명령과 원본 예약은 독립적으로 계속 동작하며, Driver가 자동으로
중단·추적하지 않습니다. 원본 예약과 새 수동 실행이 겹치지 않도록 확인하세요.

현재 자동 읽기 어댑터는 로컬 Hermes용이며 Hermes 0.18.2 환경에서 확인했습니다.
다른 플랫폼은 기존 범용 프롬프트 붙여넣기와 프로젝트 스캔 경로를 사용합니다.

## 검증 범위

중복·동시 요청·실패 주입·변경 감지·권한 검사·데스크톱/모바일 UI는 회귀 검사로
확인했습니다. 실제 Hermes 대화는 별도 Driver 저장소에 두 번 등록해 한 업무만
생성되는지와 연결 취소를 검증했습니다. 실제 업무 실행 성공을 의미하지는 않습니다.
공개 릴리스의 자동 검사는 격리된 Hermes 원본과 ACP 응답을 사용합니다. 개인 업무
기록은 배포하거나 CI에 전송하지 않습니다. [릴리스 검증 범위](release-readiness-v0.2.0.md)를 참고하세요.
