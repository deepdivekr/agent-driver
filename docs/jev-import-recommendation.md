# 가져오기에서 Jev 추천 한 곳

로컬 프로젝트 가져오기는 분석 LLM이 읽은 코드 중 예상 효율이 가장 좋은 한 지점을
선정합니다. 사용자가 후보 목록에서 기술적 선택을 다시 하지 않습니다. 적합한
근거가 없으면 추천하지 않고 기존 LLM·코드 경로를 유지합니다.

## 선정 근거

- 함수 이름뿐 아니라 모델 호출식 주변의 제한된 코드 문맥을 전달합니다.
- 같은 파일 안의 복수 판단 위치도 각각 기록합니다. 관측한 모델 호출들을 비교한
  근거가 없거나 여러 후보를 반환하면 추천 부분만 제외하고 가져오기는 유지합니다.
- 기존 처리, 반복 단위, 기대되는 절감, 다른 위치보다 우선한 이유, 필요한 입력,
  불확실할 때 기존 LLM으로 돌아가는 경로를 모두 요구합니다.
- 이 효율 추천은 기존 LLM 판단·재작업을 줄이는 지점을 우선합니다. 단순 계산,
  고정 규칙, 조회에 API를 덧붙이지 않습니다. Jev의 다른 활용을 전역적으로 금지하는
  규칙이 아니며, 범용 판단 모델의 기능 범위를 제한하지 않습니다.

## 사용자 선택과 비용

가져오기에는 추천 한 곳과 선정 이유만 표시합니다. 비용 동의는 체크 한 번이며,
동의하지 않아도 업무 초안을 저장할 수 있습니다. 추천이 없으면 비용 동의도 묻지
않습니다. 상세 화면의 기존 Jev 켜기/끄기와 서버측 비용 동의 검사는 유지합니다.

추천은 자동 코드 삽입이나 실행 승인이 아닙니다. Work의 Jev 허용 설정은 이미 연결된
판단 경로에 적용됩니다. 가져온 프로젝트의 임의 함수에 API를 주입하는 기능은
포함하지 않습니다. 이전 버전의 여러 후보는 원본 기록에 보존하지만 첫 번째를
임의로 승자로 표시하지 않습니다.

## 범위와 한계

- 최대 120개 파일/1MB, 파일당 64KB, 깊이 5, 근거 100개인 제한된 스캔입니다.
  모델/의미 판단 코드 문맥은 지점당 2,400자, 전체 32,000자까지입니다.
- 문맥은 정적 코드 발췌입니다. 전체 AST·호출 그래프나 실제 실행 빈도 분석이
  아닙니다. 키워드는 탐색 힌트이며 적합성은 LLM이 판단합니다.
- 알려진 비밀값과 자격증명 할당·URL을 가리지만 모든 개인 데이터 제거를 보장하지
  않습니다. 승인된 프로젝트 자료 사용 범위에서만 분석 LLM에 전달합니다.
- 후보 비교는 읽은 범위 안의 예상 이득입니다. 최적 위치·실제 속도·비용·정확도는
  실측하지 않았으며, 실제 데이터 비교 전에는 검증된 개선으로 표시하지 않습니다.
- Hermes·원격 OpenClaw 연결 가져오기는 별도 경로이며 이 분석을 자동 실행하지 않습니다.
- 스캔 과정에서 Jev는 호출하지 않습니다. 분석 LLM 사용량은 기존 설정을 따릅니다.

TypeSafe의 [State 문서](https://docs.typesafe.ai/concepts/state)와
[한 곳 선정·무추천 패턴](https://docs.typesafe.ai/cookbooks/skill_suggestion)을 참고했습니다.
해당 cookbook의 모델·임계값·성능 수치는 우리 제품의 검증 결과로 사용하지 않았습니다.
