# 원격 OpenClaw를 Office에서 관리하기

OpenClaw는 기존 서버에서 계속 실행하고, 로컬 Office에서 대화와 작업 결과를
확인하고 다음 지시를 보낸다. v0.2.0부터 제공하는 선택적 SSH 연결 기능이다.
호환 OpenClaw가 실행 중인 서버와 해당 환경의 SSH 인증이 필요하다.

## 이용 흐름

1. 관제센터 **가져오기 → 원격 OpenClaw**를 연다.
2. 연결된 서버에서 **서버 업무 찾기**를 누른다. 새 서버라면 이름, 주소,
   SSH 사용자·포트, Docker 컨테이너(사용 시), OpenClaw 실행 파일을 등록한다.
3. 원하는 대화 또는 예약의 **Office에 연결**을 누른다. 같은 항목을 다시
   연결해도 Work를 중복 생성하지 않는다. 이 동작만으로 업무를 실행하지 않는다.
4. 상세 화면에서 **서버 상태 새로 확인**을 누른다. 대화에서는 지시를 입력하고
   모델 사용량 안내에 동의한 후 전송한다. 서버의 기존 모델 설정을 사용한다.
5. 답변을 확인하고 **결과 확인 · 다음 지시 준비**를 누른 뒤 다음 지시를 보낸다.

Office가 실제로 실행되는 환경에 SSH 키와 서버 신뢰 기록이 있어야 한다.
Windows에서 보더라도 Office가 WSL에서 실행 중이면 WSL의 SSH 설정을 사용한다.
앱은 SSH 비밀번호나 OpenClaw 토큰을 입력받거나 복사하지 않는다. 서버의
Gateway 포트를 외부에 공개할 필요는 없다. 서버에는 Node와 OpenClaw CLI가,
컨테이너 방식이면 SSH 사용자의 Docker 실행 권한이 필요하다.

## 현재 제공 범위

| 대상 | 제공 동작 |
|---|---|
| 기존 대화 | 최근 대화 확인, 다음 지시, 이 Office가 시작한 실행 중단 |
| 기존 예약 | 예약 발견·연결·최근 실행 기록 확인 |
| MCP 클라이언트 | 대상·업무 상태 조회, 갱신, 사람에게 지시 초안 제안 |

예약의 생성·수정·실행·중지는 연결하지 않았다. 기존 서버 스케줄러가 소유한다.
MCP 도구는 원격 지시를 바로 실행하지 않는다. 사용자가 관제센터에서 초안과
사용량을 확인한 뒤 보낸다. 기존 Hermes의 도구 허용 목록과 실행 중인 Gateway는
이번 변경에서 수정하거나 재시작하지 않는다. 해당 클라이언트에서 새 MCP 도구를
쓰려면 허용 목록 갱신과 연결 새로고침이 별도로 필요하다.

## 연결이 끊겼을 때

- 요청 ID를 로컬에 먼저 저장하고 원격으로 전달한다. 같은 요청을 다시 받아도
  재전송하지 않는다. 수신 확인이 유실되면 자동 실행 대신 상태 대조가 필요하다.
- 다시 연결하면 저장된 실행 ID로 종료 여부를 확인한다. 접수, 실행 종료,
  사용자 업무의 완료는 서로 구분한다. 답변만으로 완료를 확정하지 않는다.
- 원격 응답이 없거나 규격이 바뀌면 이전 관측 기록을 보존하고 오류를 표시한다.
  알 수 없는 상태를 완료나 0건으로 바꾸지 않는다.
- 중단은 이 Office가 보낸 실행 ID에만 적용한다. 다른 실행과 컨테이너를
  종료하지 않으며, 이미 발생한 변경을 되돌려 주는 기능은 아니다.
- 상세 화면이 보일 때만 15초 간격으로 관측한다. Work마다 VM이나 브라우저를
  새로 띄우지 않는다. Office가 꺼져도 원격 예약과 실행은 서버에서 유지된다.

대화는 원본 서버의 최근 기록이므로 다른 클라이언트가 쓴 메시지도 포함될 수
있다. 민감한 토큰과 도구·추론 메시지는 표시 대상에서 제외한다. `deliver:false`는
답변의 자동 채널 전송을 끄는 옵션이지, 에이전트의 모든 외부 작업을 금지하는
샌드박스는 아니다. 실제 지시 범위와 서버의 기존 승인 정책을 유지해야 한다.

## Synology와 다른 서버

SSH로 접근할 수 있고 호환 OpenClaw가 실행 중인 Synology는 같은 연결 구조를
사용할 수 있다. NAS 자체에서는 아직 실기기 검증하지 않았다. OpenClaw가 아닌
Docker 앱이나 임의 프로젝트까지 자동 제어되는 것은 아니다. 그런 앱에는
상태 확인·지시·중단을 매핑하는 별도 실행기 어댑터가 필요하다.

이 연결은 OpenClaw **2026.9.4**의 Gateway CLI 규격을 대상으로 한다.
현재 전송은 매 요청마다 SSH와 원격 CLI를 시작한다. 상시 WebSocket 방식의
저지연 스트림이 아니다. 목록은 최신 대화
50개와 예약 100개, 대화 내용은 최근 12개로 제한한다.

## 검증 근거

- `tests/runtime-remote-office.test.mjs`: 중복·연결 유실·잘못된 응답·프로젝트 격리,
  승인·중단 범위, 실제 HTML 화면의 데스크톱/모바일 조작. 원격 서버는 fixture다.
- 공개 CI는 합성 서버 응답으로 계약과 UI를 검사한다. 개인 서버의 주소·대화·
  배포 기록은 포함하지 않는다. 모든 서버 버전의 호환성을 보장하는 검사는 아니다.

실제 업무 실행이나 메시지 전송의 성공을 주장하는 검증은 아니다.
현재 릴리스의 [검증 범위](release-readiness-v0.2.0.md)를 참고한다.
