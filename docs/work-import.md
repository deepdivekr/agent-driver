# 기존 업무 가져오기 (실험적)

관제센터의 **기존 업무 가져오기**는 다른 플랫폼의 자동화 또는 로컬 프로젝트를 Agent Office의 Work 초안으로 정리한다. 가져오기 자체는 기존 자동화·프로젝트·일정을 수정하거나 실행하지 않는다. Work의 완료 조건과 단계도 독립 검증 전에는 미확인으로 남는다.

## 세 경로

1. **다른 AI의 자동화:** 관제센터에서 범용 프롬프트를 복사해 기존 플랫폼의 AI에 붙여넣고, 반환된 JSON을 관제센터에 넣는다. 출처별 전용 커넥터나 계정 탈취 없이 시작하는 경로다. 파서는 근거 ID와 단계 의존성을 검사하고, 확인되지 않은 필드를 미확인으로 보존한다. 외부 AI가 제시한 내용은 독립적으로 검증된 사실이 아니다.
2. **워크플로 프로젝트:** 로컬 또는 WSL 프로젝트의 절대 경로를 지정한다. 최대 120개 파일·1 MiB·깊이 5의 제한 안에서 허용된 텍스트 파일만 읽는다. 비밀 파일, 링크, 바이너리와 넓은 루트는 제외한다. 코드는 실행하지 않으며 기존 일정도 켜거나 옮기지 않는다. 모델 연결과 코드 전송 승인이 이미 설정되어 있다면 제한된 신호로 목표·단계·완료 조건을 제안한다. 모델이 없거나 근거가 부족하면 사용자가 목표와 완료 조건을 직접 정한다.
3. **기존 봇 개선:** 같은 스캔으로 봇 채널·전송·에이전트 루프의 관측 근거를 구분한다. 봇으로 분류되면 기존 동작을 유지하면서 추가할 에이전트 기능을 제안한다. 개선 Work를 만든 뒤 상세 화면에서 **구현 계획 만들기**와 **다음 단계 실행**을 별도로 누른다. 기존 Git 프로젝트의 호스트 등록·쓰기 허용·모델 자료 사용 승인이 없으면 버튼 대신 필요한 연결을 안내한다. 계획 생성은 프로젝트 안에 인계 파일을 쓰고, 단계 실행은 코드를 바꿀 수 있다. 각 단계는 기존 코딩 실행기의 Git 체크포인트와 검증을 거치며, UI 버튼을 거치지 않은 MCP 호출도 저장된 승인 없이는 시작할 수 없다.

## Jev 비용·권한

Jev는 필수가 아니다. 새 Work의 Jev는 기본적으로 꺼져 있고, 프로젝트 스캔 결과를 본 뒤 API 호출 비용 가능성을 확인한 경우에만 켤 수 있다. 스캔을 분석하는 LLM은 실제 코드에서 확인된 의미 판단 지점이 있을 때만 **어느 단계에서 무엇을 짧게 판단할지, 왜 Jev 후보인지, 근거 파일·행**을 쉬운 문장으로 제안한다. 모델 사용 승인이 없거나 판단 코드 근거가 부족하면 추천을 만들지 않는다. 추천은 정적 스캔의 가설이며 반복 빈도·정확도·속도 이득은 시험 전까지 미확인이다. 추천을 만드는 과정에서 Jev API는 호출되지 않는다.

Work 상세의 **Jev 켜기/끄기**는 이후 Pack·Swarm 판단에 적용되는 Work 단위 설정이지, 추천된 특정 단계에 Jev를 자동 삽입하는 기능은 아니다. 설정과 동의 시각은 재시작 후에도 남는다. 다중 행 Pack 실행 도중에도 각 다음 판단 전에 설정을 다시 확인한다. 이미 시작된 판단이나 이전 결과를 소급해서 바꾸지 않는다. Jev를 끄거나 Jev 연결이 없으면 연결된 LLM 또는 코드 검증 경로를 사용하며, 판단 공급자가 없으면 결과를 임의로 만들어 성공 처리하지 않는다.

비용 동의와 최종 Work 저장은 로컬 관제센터의 사람 확인 경로만 제공한다. MCP의 가져오기 도구는 프롬프트 조회, 미검증 JSON 초안 저장·조회, **호스트에 등록된 프로젝트 별칭**의 읽기 전용 스캔만 제공한다. MCP 도구 호출의 `cost_acknowledged` 같은 모델 입력으로 사람의 비용 동의를 대신할 수 없다. 붙여넣은 JSON과 프로젝트 파일은 지시문이 아니라 비신뢰 자료다. 실제 비밀을 붙여넣지 않는다.

## 현재 경계

- 기존 플랫폼의 자동화 상태를 API로 직접 가져오거나 옛 일정을 자동 중지하지 않는다. 중복 발송을 막으려면 새 Work의 실행·일정 활성화 전에 사람이 이전 자동화를 확인해야 한다.
- 스캔은 정적 단서이며 실제 동작·권한·계정·완료를 보증하지 않는다. 비밀 파일 제외와 발췌 마스킹은 완전한 보안 샌드박스가 아니다. 재스캔의 변경 확인도 제한 안에서 **관측한 파일**에 한정된다. 기존 모델 자료 사용 승인이 있다면 README 발췌·파일 경로/행 단서를 연결된 AI에 전달할 수 있지만 Jev는 호출하지 않는다.
- 가져온 Work의 다단계 의도와 미확인 항목은 상세 화면에 보존된다. 등록 Git 프로젝트의 명시적 단계 실행 외에 임의 프로젝트 수정·기존 일정 활성화는 하지 않는다. 다른 플랫폼의 일정 이전, 프로젝트 자동 등록, Work 완료조건 독립 검증은 별도 작업이다.
- 실제 지원·검증 범위는 [v0.1.0 출시 기록](release-readiness-v0.1.0.md)을 따른다.
